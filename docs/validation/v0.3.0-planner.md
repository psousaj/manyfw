## Read-only planner namespace check

The test runs the real core `Planner` against fixed `PlannerInput` fixtures in a
Docker container using `--network none`. A test-only reference translation
derives nftables protocol, verdict, path, address family, source interface, and
port from the planner's typed Allow and Deny operations; it then sends UDP
loopback packets and verifies both actual verdicts and non-zero rule counters.
This reference translation exists only in the test example and is not a
production backend or `apply` path.

It checks both Applicable and Blocked plans as an unprivileged user without
`NET_ADMIN`, rejects installation from a blocked plan, and compares the nftables
ruleset before and after planner execution byte-for-byte. Only test-fixture
setup and the separate `nft list ruleset` observer retain `NET_ADMIN`, confined
to the disposable container's network namespace. The test has no Docker socket
and never targets the development host's firewall.

Run with a locally cached test image and host nftables executable:

```sh
tests/planner_readonly_namespace.sh
```

Result: passed locally; Allow and Deny packet counters incremented as expected,
and the ruleset comparison around planner execution was identical. The script
never pulls an image implicitly and returns `NotApplicable` when prerequisites
are unavailable. Compatibility CI now runs this check with a cached test image.
This bounded IPv4 loopback fixture does not establish external reachability,
complete behavior for every manager/path, enforcement, or global atomicity.

## Release gates

The release workflow builds GNU and musl artifacts for x86_64 and aarch64,
verifies SHA-256 checksums, extracts every archive, and smoke-tests packaged
executables. Those checks must pass before the workflow publishes the v0.3.0
tag and GitHub Release. No privileged firewall-write tests are part of this
read-only release.
