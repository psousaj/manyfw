# v0.2.0 discovery validation evidence

Manual end-to-end validation was run on 2026-11-05 against the local Linux
network namespace and Docker Engine (Docker 28.3.3). The original discovery,
audit, and explain operations were read-only and did not change firewall rules
or Docker resources.

## Disposable namespace

Command:

```sh
MANYFW_HOST_TEST_IMAGE=postgres:17.4 bash tests/host_namespace.sh
```

Result: passed. The disposable `--network none` container reported one
interface. Docker collection from inside that container was `Unavailable`, as
expected because the test intentionally mounts no Docker socket. The namespace
test image was already cached; the script does not pull images implicitly.

The namespace integration test was extended and rerun locally with the cached
`postgres:17.4` image. A second disposable `--network none` container toggled
loopback administrative state and added `192.0.2.77/32` and `2001:db8::77/128`
only inside its own network namespace using a static BusyBox fixture helper.
The before/after ManyFW snapshots demonstrated the state transition and both
addresses on `lo`; the Docker container was removed automatically. The test
performed no host routing or firewall changes. The collector itself has no
mutation API and ran read-only in both snapshots.

## Live Docker and host snapshot

Command:

```sh
cargo run --locked -p manyfw -- discover --output /tmp/opencode/manyfw-v020-live-snapshot.json
```

Result: snapshot version 1; Docker outcome/completeness `Complete`; six running
container observations with observed endpoints; host discovery returned 15
interfaces, 9 addresses, 33 listeners, and 45 routes. The snapshot was written
outside the repository and is not committed because it describes local
infrastructure.

## Audit and Explain over that snapshot

Commands:

```sh
cargo run --locked -p manyfw -- audit \
  --file examples/manyfw.toml \
  --snapshot /tmp/opencode/manyfw-v020-live-snapshot.json --format json
cargo run --locked -p manyfw -- explain docker:<unique-observed-service> \
  --file examples/manyfw.toml \
  --snapshot /tmp/opencode/manyfw-v020-live-snapshot.json --format json
```

Both commands produced valid JSON. Audit returned schema v1 with 45 findings.
Explain returned schema v3 with two endpoint paths, 12 evidence records, and an
`unknown` runtime conclusion. This correctly avoids claiming verified
reachability or firewall enforcement from observation alone.

## Local automated checks

On 2026-11-05, the following commands passed locally with Rust 1.85.0:

```sh
cargo +1.85.0 fmt --all -- --check
cargo +1.85.0 clippy --workspace --all-targets --locked -- -D warnings
cargo +1.85.0 test --workspace --locked
cargo +1.85.0 build --workspace --locked
```

The compatibility workflow is updated so PRs run its disposable host
namespace, distro smoke, and integration-contract jobs; a `NotApplicable`
result for the required namespace smoke is a CI failure. Those hosted checks
must pass on the release-candidate PR before it can merge. Local validation is
not a substitute for those pending CI results.
